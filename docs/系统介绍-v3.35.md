## 一句话概括

一个**零依赖、单文件、离线可用**的个人健康管理仪表盘。仓库内置一套**中性示例画像**（30 岁男性 · 脾虚湿蕴体质 · 每周 3-4 次抗阻训练 · 目标薄肌），全站的训练目标、饮食门槛与相关文案都锚定在这份画像上，可通过同目录的 `profile.local.js` 覆盖为自己的真实画像（该文件已被 `.gitignore` 排除，不会进仓库）。系统把训练、饮食、补剂、中医养生、松解恢复、抗老抗衰、护肤七大维度整合在同一个浏览器页面中，并且**已经形成闭环**——记录训练 → 引擎算下次目标 → 给出今日建议 → 睡眠不足自动减量 → 周容量仪表回看肌群分布。**所有条目均附证据等级（A/B/C/D）、失败模式编码与个性化禁忌提醒**。

## 一、系统定位

| 维度 | 说明 |
|---|---|
| **服务对象** | 内置**示例画像**（非泛用产品）—— 30 岁男性 · 175cm / 70kg · 体脂 20% · 目标薄肌；真实画像由 `profile.local.js` 注入，不进仓库 |
| **健康锚点** | 脾虚湿蕴体质（示例）· 久坐 8 小时 · 湿热气候 |
| **训练方向** | 薄肌（降体脂保肌）· 8-15RM 代谢压力模式 · 每周 3-4 次（推/拉/腿 + 功能稳定/活动度） |
| **饮食目标** | 热量 1900-2400 kcal（温和缺口）· 蛋白 1.6-2.2 g/kg（训练日 ≥120g） |
| **设计约束** | 单文件 HTML · 零构建工具 · 核心功能离线可用（动作演示媒体按需在线加载、离线自动降级，不影响其余功能）· 浏览器本地存储持久化 |

**核心理念**：所有健康决策必须有**证据等级**标注；每个动作/补剂/成分必须编码**失败模式**（常见失败 → 一线修复 → 兜底）；并从**现代运动科学**与**传统中医养生**双视角交叉分析；能算的绝不让模型自己拍（见 §6 原则 6）。

## 二、系统架构

### 2.1 技术形态

```
单个 HTML 文件
├── <style>     全部 CSS（设计令牌 + 组件样式 + 响应式断点 + 浅色主题作用域）
└── <script>    全部 JS（IIFE 模块化，"use strict"）
```

零框架 · 零构建 · 无字体外链 · 无 API 调用 · 纯浏览器本地运行。唯一的外部引用是**动作演示媒体**（两个开源数据集，经 jsDelivr 分发，`loading="lazy"` 按需加载；加载失败自动隐藏并提示「动画未加载」，离线不影响其余全部功能）。

`<head>` 内另有一段**极简防闪烁脚本**：在首次绘制前把 `data-theme` 写到 `<html>` 上，否则浅色模式会先闪一下深色（FOUC）。测试定位主脚本时须避开它（见 `tests/verify-logic.js` 注释）。

### 2.2 数据与逻辑分层（v3.23 重构重点）

旧版把 775 行知识库常量与持久化逻辑塞在同一个 `Store` 里（841 行），读逻辑要先翻 775 行数据。v3.23 拆为四层：

| 模块 | 行数 | 职责 |
|---|---|---|
| **Util** | 20 | 通用工具：本地日期口径、周一基准、深拷贝 |
| **KbData** | 818 | 静态知识库常量（**纯数据字面量，零逻辑**） |
| **Schema** | 110 | 数据结构定义 + `normalize()` 规范化 + 版本迁移 |
| **Store** | 187 | 持久化：读写 / 滚动备份 / 导入导出 / 失败上报 |

> 拆分收益：`Schema.normalize()` 是风险最高、最需要单测的一块，现在与持久化彻底分开，可独立测试（本次即通过 59 条逻辑层断言直接验证）。

### 2.3 业务模块（14 个）

> 下表行数＝模块 IIFE 主体行数（不含上方注释块），19 个模块合计 **3,196 行**。

```
Library（动作库 30）   Plan（计划 6）      Log（记录 10）
Progress（进度 46）    Diet（饮食 53）     Body（身体数据 18）
Adapt（自适应引擎 75） Supplements（补剂 12） Herbs（中医 13）
Release（松解 17）     Longevity（抗衰 13） Skin（护肤 13）
Theme（主题 35）       SwipeTab（手势 107）
```

- 其中 5 个知识库模块由 **`kbBase()` 工厂**统一产出——它们结构完全同构（静态条目 + 用户清单 id 数组），旧版各写一遍 `toggle` 导致"5 份实现里只有 4 份做了空数组防护"，工厂化后彻底消除该不一致（也是这 5 个模块 IIFE 只剩 12-17 行的原因：真正逻辑都在工厂里）。
- **Body** 是 v3.29 训练闭环引入的数据层：睡眠 / 柔韧 / 舌象三类记录，同日 **upsert**（同日期覆盖而非追加），统一走 `Store`。
- **Adapt** 是确定性判定引擎（**不给模型留打分空间**）：`e1RM` 用 Epley 近似 `w × (1 + reps/30)`，只用于同动作的组间/次间比较；全部系数写死在模块顶部（`PCT_UP` / `SLEEP_PENALTY` / `REST_GAP_DAYS`），调参只改一处。

### 2.4 展示层

`UI` 模块（1,603 行）：路由 + 12 个页面渲染 + 渲染助手 + 事件委托。
受「单文件 / 零依赖」硬约束不做物理拆分，改为**建立 `Pages` 入口索引**集中登记：

```js
const Pages = {home, plan, library, log, diet, progress,
               supps, herbs, release, longevity, skin, data: dataView};
```

新增一个 Tab = `TAB_GROUPS` 加一条 + `Pages` 登记同名函数。Tab 定义（分组 / 组内顺序 / 显示名）**单一真相**在 `TAB_GROUPS`，不再维护两个数组。

### 2.5 关键健壮性机制

| 机制 | 作用 |
|---|---|
| `Schema.normalize()` | 所有外部数据（本地存储 / 导入 JSON）进入前统一补齐字段，渲染层永不因缺字段抛错；**幂等** |
| 渲染错误边界 | 任一页面渲染异常 → 兜底错误页 + 数据导出通道，绝不留白屏 |
| 滚动备份 | 导入 / 版本迁移前自动留档，最多保留 3 份，可在备份页一键回滚 |
| 写入失败上报 | 本地存储写失败（配额满 / 隐私模式）→ 立即 toast，**不再静默丢数据** |
| 损坏数据抢救 | 本地存储解析失败时，原始串另存到 `.corrupt` key 供导出抢救，绝不静默丢弃 |
| 删除黑名单 | 内置动作删除后记入 `removedBuiltin`，不再被下次加载自动回灌 |

> ⚠️ **错误边界是双刃剑**：单页崩溃不再白屏，但也把错误**藏进**错误面板——回归测试必须断言「真实内容渲染」，不能只断言「页面没报错」。v3.34 修的就是这类漏网 bug（见 §9）。

### 2.6 个人画像注入层（v3.35 开源脱敏引入）

开源仓库不能携带作者的真实身体数据，但本系统全站的训练目标、饮食门槛与大量文案都锚定在一份具体画像上。解法是**把画像抽成可注入的一层**：

```js
// index.html 顶部：内置中性示例值
const PERSONAL = Object.assign({age:30, sex:'男', height:175, weight:70,
  bodyfat:20, muscleRate:null, city:'', tdee:null, goal:'薄肌 (降体脂保肌)'},
  (typeof window !== 'undefined' && window.__TM_PROFILE__) || {});

// 由画像推导的区间——改画像即自动跟随，不写死在文案里
const DERIVED = (function(){ /* 瘦体重 / 有氧心率区间 / 蛋白区间 / BMR / TDEE */ })();
```

- `<body>` 内主脚本之前有一行 `<script src="profile.local.js"></script>`。该文件**已被 `.gitignore` 排除**，仓库里不存在；不存在时浏览器静默跳过，页面回落到示例值。
- 用户把 `profile.local.example.js` 复制为 `profile.local.js` 填入真实画像即可，无需构建、无需改代码。
- `Diet` 模块的目标区间同样支持 `window.__TM_TARGETS__` 覆盖。
- **可空字段**（`muscleRate` / `city` / `tdee`）留空时相关文案**不渲染**，绝不输出 `null`——文案层统一经 `DERIVED.*Text` 取值，缺值即回落中性表述。

> 这套机制同时带来一个副作用收益：画像从"写死在文案里的数字"变成"单一来源的常量"，改一次画像全站文案自动跟随，不再需要满文件搜索替换。

## 三、12 个功能模块

### 3.1 概览（首页）
打开即见的仪表盘：个人信息卡（目标/体重/体脂/本周训练次数/RM 模式/有氧心率区间）· **核心禁忌提醒**（红色面板，6 条安全提醒，第一眼可见）· **今日建议**（基于同动作历史 + 昨夜睡眠的自适应目标重量）· **周容量仪表**（六肌群最近 7 天总组数 vs 10-20 组/周参考带）· **昨夜睡眠快捷打卡**（今日建议 -10% 联动的数据源）· **我的事项**（5 个模块的进度条 + 条目状态，不用逐个点 Tab，点击可跳转定位）· 本周训练日表格（当天高亮）· 吃练匹配 · 进度反馈 · 页面底部附可折叠的**术语对照表**（RM、TDEE、RDL、BSS 等英文缩写与行话的白话解释）。

### 3.2 计划制定
内置「推拉腿 + 功能稳定 + 活动度」周计划模板，支持逐天编辑动作（多选）。
- **热身清单**（折叠）：5 分钟动态热身 8 个动作（猫牛式 / 肩绕环 / 髋绕环 / 弓步转体 / 臀桥 / 靠墙踝背屈 / 开合跳 / 徒手深蹲），并注明"力量正式组前再用 50% 重量做 1 组热身组"。
- **重点部位★倾斜**：设定本阶段弱项肌群后，本周计划中该肌群动作自动标 ★，并提示"容量可向其倾斜 10-20%"。
- 旧版计划按「周五动作序列精确签名」迁移；**v3.23 起改为按天迁移**——只有签名命中历史默认的那一天会被升级，其余各天的自定义排布原样保留。

### 3.3 动作库（43 个内置动作）
按 6 类组织：推 / 拉 / 腿 / 核心 / 有氧·功法 / 功能·稳定。每个动作含：基础信息、要点、常见错误、**失败模式**（现象 → 一线修复 → 兜底）、**权威演示源外链**（ExRx / 百度百科等，不使用 AI 生成配图）。支持搜索、分类筛选、增删改（自定义动作以 `id_` 前缀区分）。

**演示媒体（v3.24 起）**：43 个动作中 **36 个**内置开源数据集演示——**动画 GIF（25 个）** 来自 exercises-dataset（github.com/hasaneyldrm，数据 MIT / 媒体 © Gym visual）、**起止位图（11 个，各 2 张）** 来自 free-exercise-db（github.com/yuhonas，Unlicense 公共领域），经 jsDelivr 分发、`loading="lazy"` 按需加载；加载失败自动隐藏并提示「动画未加载」，离线不影响其余全部功能。其中 25 个动作（即全部 GIF 动作）另附**中文分步**（`**要领**` 琥珀高亮，每步至多 1 处）与**协同肌群**标注。另有 38 个动作附**权威演示链接**（`demo` 字段，exrx.net 等外链，与内嵌媒体是两套独立机制）。

**v3.26 新增 4 个功能/稳定动作**：靠墙踝背屈拉伸、胸小肌靠墙松解（筋膜球）、泡沫轴胸椎伸展、摩腹（健脾助运化）。
**v3.29 新增**：楼梯机（时间效率最高的有氧，兼顾下肢肌力刺激），并替换周二有氧；动作库 42 → **43**。

### 3.4 训练记录
选择日期 + 训练日 → 自动加载当日动作 → 逐组记录重量次数 → **逐动作 RPE**（1-10 保留感，下拉 7-10 步长 0.5，默认 8，可留空「不记」）→ 训练评分 + 恢复状态 → 历史表格化。

### 3.5 饮食打卡
录入热量与蛋白 · 3 个布尔标记（油脂≥15% / 无含糖饮料 / 蔬菜≥500g）· **自动识别训练日**（当天有训练记录则蛋白门槛升至 120g）· 吃练匹配实时判定 · 近 7 天矩阵 · 每周反馈。
**v3.23 修正**：热量未填或低于下限时不再落进「达标」分支产生绿色空提示。

### 3.6 进度反馈
体测趋势（体重/体脂/肌肉率/腰围，排除 `null` 点）· 周完成度反馈 · **柔韧自测**（v3.29 新增，P1）：坐位体前屈 cm（可为负，越大越好）+ 深蹲最低点髋高 cm（越小越深），每 2 周同条件测一次，列表含 vs 上次差值。

### 3.7 补剂循证库（17 条）
4 级分类：基础必备（5）/ 日常基础（2）/ 可选（3）/ 已排除（7）。每条含证据等级、安全性、作用、剂量、时机、副作用、禁忌、相互作用、失败模式、循证来源（具体到 RCT 数量/人数/期刊/年份）。

### 3.8 中药中医（11 条）
药食同源（6）/ 经典方剂（3）/ 起居功法（2）。药食同源条含性味归经、功效、适用体质、用量、禁忌；方剂条**仅作溯源科普，禁止自行抓药**。底部附「体质适配要点」（先化湿后进补 / 虚不受补 / 炒薏米 vs 生薏米 / 与补剂模块联动 / 化热信号识别）。

v3.29 起本页新增两个面板：
- **节气面板**：内置 24 节气近似日期表（每年漂移 ±1 天可接受），按示例体质（脾虚湿蕴）给定制提示（如秋分=润燥健脾、大雪=热身延长到 8 分钟）。
- **舌象周记**：晨起空腹自然光下观察，记录苔色（白腻/白腻微黄/淡白/黄腻/少苔）+ 厚薄（薄/中/厚）+ 备注；苔色由白腻转黄腻 = 湿郁化热信号。首次记录即自动成为「首辨基线」，此后每周同条件对比看趋势（基线数据存本地，不随仓库分发）。

### 3.9 松解恢复（17 条）
恢复基石（3）/ 松解工具（5）/ 分部位方案（4）/ 中医手法（5）。含操作参数与禁忌（如「腰方肌区只放外侧半」「避开膝窝正后方」）。核心优先级：**睡眠与营养 > 主动恢复 > 自我松解 > 被动手法**。页面顶部按当天训练日自动推荐对应松解方案。

### 3.10 抗老抗衰（20 条）
生活习惯（10）/ 补剂营养（6）/ 行为动作（4）。核心结论：运动、植物为主饮食、热量限制是证据最充分的抗衰干预。含「抗衰补剂祛魅」与「处方药类抗衰（严禁自行使用）」两条，这两条以灰化样式呈现，与护肤模块的祛魅条视觉统一。

### 3.11 护肤（17 条）
基础必备（6）/ 可选加成（7）/ 已排除·祛魅（4）。核心结论：**防晒**是唯一被 RCT 证实能延缓皮肤光老化的单一干预；**维A类**是抗皱证据最强的活性成分。每条含浓度、时机、副作用、禁忌、配伍、**参考价**、证据 DOI、失败模式。附定制的早C晚A流程 + 三档预算（¥100 / ¥300 / ¥600 每月）+ 时间轴预期 + 10 条零成本习惯建议。

### 3.12 数据 / 备份
导出 JSON（并记录导出时间）· 导入 JSON（**结构非法一律拒绝并说明原因**，合法导入前自动留档）· 立即留档 · 恢复默认数据 · **本地自动留档列表**（导入前 / 迁移前 / 手动，可一键回滚）· 上次导出时效提醒。

### 3.13 训练闭环（v3.29 起，跨概览 / 记录 / 进度 / 计划四页）

这是系统从「知识库」变成「闭环」的一次升级，规则全部确定性写死：

| 环节 | 实现 |
|---|---|
| **采集** | 训练记录逐动作记组次 + RPE；Body 记睡眠（小时/质量）/ 柔韧 / 舌象 |
| **判定** | `Adapt.suggestion()` 按上表规则给出目标重量（`e1RM` = Epley 近似） |
| **联动** | 昨夜睡眠 <6h → 目标重量再 **-10%**；记录超 1.5 天视为过期不参与联动 |
| **回看** | 周容量仪表按最近 7 天汇总六肌群组数，对照 10-20 组/周参考带（不含功法/有氧） |
| **倾斜** | 计划页设定重点部位后，该肌群动作标 ★ 并提示容量倾斜 10-20% |

`Adapt` 规则表（系数写死在模块顶部，调参改一处）：

| 条件 | 动作 |
|---|---|
| 上次 e1RM ≥ 前高 × **1.02** | 重量 **+2.5%**（四舍五入到 0.5kg）上探 |
| 上次达前高但未上探 | 维持，可加 1 次或 1 组 |
| 上次未达前高 | 维持，动作质量优先 |
| 距上次 ≥ **5 天** | 恢复性回归（组次减半热身） |
| 昨夜睡眠 < **6h** | 目标重量再 **-10%** |

### 4.2 浅色主题（v3.32 新增）

`[data-theme="light"]` 作用域内整体重定义令牌，**不是**简单反色——深色下靠"亮度阶梯"表达层级，浅色下改为"冷灰底 + 纯白卡片"表达：

| 令牌 | 深色 | 浅色 |
|---|---|---|
| `--surface-0` | `#0a0c10` | `#f5f6f9` |
| `--surface-1` / `-2` | `#13161c` / `#1c2029` | `#ffffff` / `#ffffff` |
| `--surface-3` | `#282d38` | `#eef0f5` |
| `--txt-1` | `#e6e9ef` | `#15181e` |
| `--txt-inv` | `#08101a` | `#ffffff` |
| `--accent` | `#4f9dff` | `#4f57d4` |

语义轴与分类轴同步换色（`--st-ok:#0b7a52` · `--st-warn:#8a5600` · `--st-bad:#c02a2a` · `--cat-1..8` · `--tier-1..4`），**全部数值经 WCAG 对比度核验**而非肉眼判断。所有色值均取"同色相压暗"而非换色相，保证语义可辨。

> 已知取舍：浅色下 `--surface-1` 与 `--surface-2` 同为白色，表格行悬停若沿用 `--surface-2` 会不可见——故在浅色作用域内单独把 `table.data tbody tr:hover` 改为 `--surface-3`。此规则只在浅色生效，深色不受影响。

**三态切换**（`Theme` 模块）：`auto`（跟随系统）/ `light` / `dark`，存在 `thinMuscle.theme.v1`；处于 `auto` 时监听 `matchMedia` 实时跟随系统切换。不支持的 `localStorage` 值一律回落 `auto`。

### 4.3 三轴色彩语义（本系统的色彩纪律核心）

| 轴 | 令牌族 | 用法 | 规则 |
|---|---|---|---|
| **status** | `--st-ok` / `--st-info` / `--st-warn` / `--st-bad` / `--st-mut` | 表达**状态** | **唯一允许填充的轴** |
| **cat** | `--cat-1..8` + `--cat-0`（9 色池，无序分类） | 表达**分类** | 只用文字色 + 描边，**禁填充** |
| **tier** | `--tier-1..4` | 表达**有序分级** | 只用文字色 + 描边，**禁填充** |

动作色 `--accent` 独用于「可交互」，禁止用于表达判定。

**字段标题的色彩归属**：动作库的字段标题按语义分流到两条轴——「要点」= `ok` 绿、「常见错误」= `bad` 红（status 轴，表达对错状态）；「协同肌群」= `c5` 青、「中文分步」= `c2` 琥珀、「动画演示」= `c7` 紫、「演示」= `c6` 蓝（cat 轴，表达信息类别）。新增字段标题时先判断语义归属哪条轴，**不要一律用 `mut` 灰**，否则视觉层级塌陷、扫读失效。

**中文分步的要领标注**：数据侧用 `**…**` 标记动作关键 / 安全要点 / 易错处，渲染时经 `rich()` 转 `<b>` 后统一升级为 `.key`（琥珀加粗 + 淡琥珀底）。标注原则为**每条分步最多 1 处**，不标「重复所需的重复次数」这类无信息量步骤（当前 25 个动作 / 70 处要领，回归测试直接断言该 70 处）。

### 4.4 响应式断点与移动端

`479px`（Tab 字号收敛）· `767px`（表格转卡片、导航简化为纯图标条）· `768px` 起双栏 · `1023px`（分组标签隐藏）· `1024px` 起三栏。
另针对 `pointer:coarse` 全局提升触控目标至 44px。

**移动端手势切换（v3.33，`SwipeTab` 模块）**：仅小屏（≤767px）启用，手指左右滑动切换模块，左滑下一个 / 右滑上一个；桌面端完全禁用，保留点击切换。四个阈值防误触：

| 参数 | 值 | 含义 |
|---|---|---|
| `MIN_DIST` | 60 px | 慢速拖动至少滑这么远才触发 |
| `MIN_DIST_FLICK` | 30 px | 快速轻扫（flick）时滑这么远即可 |
| `MIN_VEL` | 0.3 px/ms（≈300 px/s） | 轻扫的速度门槛 |
| `DIR_RATIO` | 1.5 | `\|dx\| > \|dy\| × 1.5` 才接管，否则判定纵向滚动、**完全不拦截** |

不拦截区域：`.tabs`（横向滚动的标签栏）/ `.chart-wrap` / `.table-wrap` / `[data-no-swipe]`。首/尾只做轻微回弹提示，不越界。动画沿用 `--dur-3` + 退出曲线，只动 `transform` + `opacity`；`prefers-reduced-motion` 下动画禁用但**切换功能不受影响**。

### 4.5 无障碍

`:focus-visible` 焦点轮廓（2px + 2px offset）· `prefers-reduced-motion` 全局降级 · `prefers-contrast:more` 加深描边与次要文字 · `aria-live` toast · `role="tablist"/"tab"/"tabpanel"` + 方向键导航 · 表单 `label[for]` 全量关联 · 确认弹窗为 `role="dialog"` + `aria-modal` + 焦点管理 + Esc 关闭（替代原生 `confirm`）。

## 六、核心设计原则

1. **循证分级**——每条建议标注 A/B/C/D 证据等级，A 级必须有人体 RCT 支撑
2. **失败模式编码**——不只写「正确怎么做」，必须写「失败了怎么办」
3. **高风险行动黑名单**——独立列出绝对禁止项（孕期禁用 / 有毒药材 / 违禁物质）
4. **可执行具体性**——禁止「可以考虑 / 根据情况」等软化措辞，必须给「区间 + 触发条件」或「判定 + 分支」
5. **双视角整合**——训练营养以现代科学为主 + 中医补充；养生以中医辨证为主 + 现代证据校验；冲突时如实并列
6. **确定性判定**——体质评分、热量计算、进阶判定一律走脚本/公式，**模型不给自己打分**（自评不可信）
7. **置信度标注**——结论标注依据等级与不确定性
8. **换框架重审**——重要结论用另一套框架交叉复审
9. **数据可对账**——所有趋势结论必须能追溯到有效数据点；数据不足时**明确拒答**而非编造结论
10. **说中文**——禁裸用英文缩写与行话，首次出现必须给中文全称 + 位置说明（RDL→罗马尼亚硬拉，练大腿后侧的髋铰链动作）

## 八、使用方式

0. **（可选）配置自己的画像**：把 `profile.local.example.js` 复制为同目录下的 `profile.local.js`，填入真实年龄/身高/体重/体脂等。不配置则使用内置中性示例值；该文件已被 `.gitignore` 排除，不会进仓库（见 §2.6）
1. 用任何现代浏览器打开 `index.html` —— 无需安装、注册、联网、服务器
2. 数据自动从浏览器本地存储加载，首次使用为默认数据
3. 点击顶部 Tab 切换 12 个模块；**手机端可左右滑动切换**
4. 右上角按钮循环切换主题：跟随系统 → 浅色 → 深色
5. 在补剂 / 中医 / 松解 / 抗衰 / 护肤模块点「+ 加入我的清单」建立个人方案
6. 每次训练后在「记录」页逐组录入重量次数与 RPE；概览页的**今日建议**会自动给出下次目标
7. 每天起床顺手在概览页打卡昨夜睡眠——睡眠 <6h 时今日建议自动减量 10%
8. 概览页自动汇总进度与禁忌提醒
9. **定期到「备份」页导出 JSON**——本地存储可能被浏览器清理（Safari 会清理 7 天未访问站点的数据），导出后存到网盘；换设备时导入即可恢复
