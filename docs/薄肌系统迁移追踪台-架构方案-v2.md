### 0.2 D4 技术评估：不改名是对的

你的判断成立，我核过依赖面：

| 引用点 | 是否受影响 |
|---|---|
| 逻辑层读取（`KbData.DATA` 合并 `window.__TM_PROFILE__`） | 不改名则零改动 |
| 你本地的 `profile.local.js` | 不改名则**你不用动任何文件** |
| `profile.local.example.js`（开源模板） | 不改名则模板不用改 |
| `docs/` 三份文档 | 不改名则文档不用改 |

**唯一代价是保留一个 `TM` 前缀**。但这里有个容易忽略的点：**D1 定了内容以薄肌系统为基准，那这个应用本质上仍是「薄肌系统」，只是换了外观。** 所以 `TM` 前缀在语义上依然成立，不是残留。

> 补充：该标识符只出现在 `window` 全局与本地脚本里，**不进入任何 UI**，因此与「不得残留薄肌系统的 UI 展示效果」这条要求毫无冲突。

### 0.3 ⚠️ 修正 v1 的建议：存储键不应改名

v1 我建议把存储键改成 `workbench.train.v1`。**D3 确认后，这个建议应当撤回。**

| | v1 建议 | v2 修正 | 理由 |
|---|---|---|---|
| 主数据键 | `workbench.train.v1`（改名） | **保持 `thinMuscle.trainSys.v1`** | 键里存着**你的真实训练数据**。改名 = 必须写迁移 + 承担数据风险；不改名 = 零风险 |
| 备份键 | `workbench.backup.v1.` | **保持 `thinMuscle.backup.v1.`** | 同上 |

**判据与 D4 完全一致：不必要就不改外部契约。** v1 之所以要改名，是因为当时要合并两套数据；现在只有一套数据、且是你的真实数据，改名的唯一收益是命名洁癖，成本却是真金白银的数据迁移风险 —— 不划算。

### 3.3 色轴收敛（设计决策，非技术细节）

源系统有严格三轴契约：status 可填充 / cat 8 色仅描边 / tier 4 级仅描边。追踪台调色板只有 5 色容量。

| 源语义 | 目标 | 处理 |
|---|---|---|
| status `ok`/`info`/`warn`/`bad`/`mut` | `--primary` / `--primary-dark` / `--yellow` / `--danger` / `--muted` | 1:1 映射 |
| tier 4 级 | `.status-tag` 三态 | 4 级压到 3 档，最低档并入中性 |
| **cat 8 色 + 四个扩展标题色** | **收敛为中性描边 + 字重分层** | **收敛**：分类靠文字，不靠颜色 |

**收敛的理由**：追踪台的视觉语言用**层级与留白**表达结构，用**颜色**只表达状态。强留 8 色分类轴会与状态色互抢注意力，且目标体系没有这个容量。代价是动作库与知识库卡片会「素」一些，收益是全站色彩语义唯一。

## 5. 本次核查新发现的三件事

### 5.1 `state.profile` 是个「半死字段」

核查结论（逐处验证，非推测）：

| 事实 | 证据 |
|---|---|
| `state.profile` **只有 1 处活的消费者** | `renderChart()` 用 `profile.goalWeight` 画图表目标线（兜底 63） |
| `home()` 里 `const p=Store.get().profile` **声明后从未使用** | 该函数内 `p.` 引用数为 **0** —— 死代码 |
| **没有任何画像编辑 UI** | 全站无 `pf_*` / `prof_*` 表单 id |
| 真正驱动个性化的不是它 | 内容个性化走 `KbData.DATA` ← `window.__TM_PROFILE__` / `__TM_TARGETS__` |

**含义**：`state.profile` 目前**只能靠手改 `profile.local.js` 或干脆不动**。这正好是追踪台首次设置引导能补上的缺口 —— 见 §6 的 D6。

### 5.2 有 6 条规则与页面结构耦合，需重映射

D2 保留颜色自定义后，我核查了它的 16 条覆盖规则 **以及与之配套的基础样式**，发现 **6 条规则绑定了追踪台的页面结构**（全部依赖 `#page-today`），页面重写后必然失效：

| 上下文 | 规则 | 处置 |
|---|---|---|
| 基础·浅色 | `#page-today>.grid>.card:nth-child(2)`（暖色底 `#efe3d8`） | 需重新指向新总览页的目标卡片 |
| 基础·浅色 | `#page-today>.grid>.card:nth-child(3)`（青绿底 `#dce8e2`） | 同上 |
| 基础·深色 | `#page-today>.grid>.card:nth-child(2)` | 同上 |
| 基础·深色 | `#page-today>.grid>.card:nth-child(3)` | 同上 |
| 自定义色 | `#page-today>.grid>.card:nth-child(2)` → `--custom-button-soft` | 同上 |
| 自定义色 | `#page-today>.grid>.card:nth-child(3)` → `--custom-primary-soft` | 同上 |

**这 6 条其实是同一个设计手法的三种主题变体**：追踪台给「今日总览」的前两张卡上不同底色做视觉分组。

处置建议：**保留这个手法，但改用显式类名**（如 `.card.tint-peach` / `.card.tint-mint`）替代 `:nth-child` 结构选择器。理由：`:nth-child` 依赖卡片顺序，将来任何插卡/移卡都会静默错位；显式类名一次修好，且三种主题变体可收敛为一处令牌引用。

自定义色块的其余 13 条（`.sidebar` `.hero` `.primary-btn` `.progress>i` `.ring` `.segmented` `.set-check` `.check-toggle` `.day-plan.today` `.chart-tooltip` `.food-option` `.input:focus` `.nav-btn.active`）**全部继续有效** —— 这些组件名在新页面里继续使用。

### 5.3 追踪台的双语层在新架构下变成死重

追踪台的 `I18N` 字典以中文串为 key，覆盖的是**它自己的页面文案**。D1 丢弃其 7 页后，字典约 90% 失效；而保留的 `translateTree` MutationObserver 会在每次 DOM 变更时遍历全树 —— 对一个含 13 页、大量表格与卡片的 DOM 是持续开销。

同时，薄肌的内容是 57,681 字符的**领域中文**（中医经方、术语表、循证说明），机翻质量不可接受，你个人也不需要英文界面。

→ 见 §6 的 D5。
