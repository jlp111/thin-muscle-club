## 一、脱敏架构：三层防护

开源仓库与本地私有使用是**两套数据**，靠三层机制隔离。

| 层 | 机制 | 作用 |
|---|---|---|
| **第 1 层 · 画像注入** | `index.html` 内置中性示例画像 → `profile.local.js` 覆盖 | 让"全站锚定一份具体画像"与"仓库不能含真实数据"两个矛盾需求同时成立 |
| **第 2 层 · 忽略规则** | `.gitignore` | 阻止含真实数据的文件被 `git add` 意外纳入 |
| **第 3 层 · 匿名身份** | 仓库级 `user.name` / `user.email` | 提交历史里的作者信息不带真实姓名与邮箱 |

### 1.1 画像注入层（第 1 层）

`index.html` 顶部定义 `PERSONAL` 常量，内置**中性示例值**；若同目录存在 `profile.local.js`，其 `window.__TM_PROFILE__` 会覆盖示例值：

```js
const PERSONAL = Object.assign(
  { age: 30, sex: '男', height: 175, weight: 70, bodyfat: 20,
    muscleRate: null, city: '', tdee: null, goal: '薄肌 (降体脂保肌)' },
  (typeof window !== 'undefined' && window.__TM_PROFILE__) || {}
);
```

全站身体数值、有氧心率区间、蛋白区间、TDEE 均由 `PERSONAL` **推导**（`DERIVED` 常量），不再写死。因此：

- **仓库里**（无 `profile.local.js`）→ 渲染中性示例值，任何人 clone 下来都能跑。
- **你本地**（有 `profile.local.js`）→ 渲染你的真实数据，体验与脱敏前一致。

`profile.local.example.js` 是入库模板；`profile.local.js` 被排除。**文件不存在时自动回落**，所以缺了它不会报错。

### 1.2 忽略规则（第 2 层）

`.gitignore` 排除的内容分四类：

| 类别 | 条目 | 原因 |
|---|---|---|
| 本地画像 | `profile.local.js`、`profile.local.*.js` | 含真实身体数据 |
| 开发记录 | `.workbuddy/` | 含健康数据与内部笔记 |
| 历史备份 | `index.html.bak-*`、`*.bak-*`、`*.pre-*` | **脱敏前的旧文件，含真实数据** |
| 旧版文档 | `docs/系统介绍-v3.28.md` | v3.34 之前的版本含真实身体数据 |

> ⚠️ **一个已修复的坑**：`profile.local.*.js` 这个通配符会把**必须入库**的模板 `profile.local.example.js` 一起匹配掉。已补 `!profile.local.example.js` 显式放行。**该 `!` 行的顺序必须在通配符之后**，否则不生效——`.gitignore` 是自上而下逐行覆盖的。

### 1.3 匿名提交身份（第 3 层）

```bash
git config --local user.name  "ThinMuscle Dev"
git config --local user.email "dev@example.com"
```

`--local` 表示只对本仓库生效，**不影响你的全局 Git 身份**（全局身份里的真实邮箱不会被写进本仓库的提交历史）。这是关键：Git 提交历史里的作者邮箱是公开可见的，且**改起来很麻烦**。

## 三、推送流程

### 3.1 首次推送（一次性）

**第 1 步 · 在 Git 平台创建空仓库**

在 GitHub / Gitee 等平台新建仓库。建议：

- **不要**勾选"添加 README / .gitignore / LICENSE"——避免与本地已有提交冲突，省去一次 merge。
- 若希望仓库公开可检索，选 **Public**；若只是自用备份，选 **Private**（Private 仓库不构成"开源发布"，但同样建议保持脱敏）。

**第 2 步 · 关联远程并推送**

```bash
cd ~/WorkBuddy/2026-08-26-11-51-25
git remote add origin <你的仓库地址>
git push -u origin main
```

**第 3 步 · 推送后立即核验**

```bash
# 确认远程上确实没有敏感文件
git ls-tree -r origin/main --name-only
```

在输出里确认**没有** `profile.local.js`、`*.bak-*`、`.workbuddy/`、`docs/系统介绍-v3.28.md`。然后打开平台网页端，逐项确认：

- 提交记录的作者名与邮箱是 `ThinMuscle Dev <dev@example.com>`；
- 文件列表与 `git ls-files` 一致（13 个文件）。

### 3.2 日常同步（每次改动后）

```bash
cd ~/WorkBuddy/2026-08-26-11-51-25

# 1) 先跑回归，绿了再提交
sh tests/run.sh

# 2) 看清单——这一步不要跳过
git status --short

# 3) 只加你要提交的文件（不要用 git add -A / git add .）
git add index.html README.md

# 4) 提交前终检：暂存区里有无敏感内容
git diff --cached | grep -niE '(api[_-]?key|secret|token|password)[[:space:]]*[:=]|(mongodb|mysql|postgres|redis|jdbc)://|/Users/'

# 5) 提交并推送
git commit -m "feat: 描述你的改动"
git push
```

> **为什么强调"不要用 `git add -A`"**：它会无差别暂存所有未忽略文件。一旦你临时建了个含真实数据的文件（比如导出的体测 JSON）而它**恰好没被 `.gitignore` 覆盖**，就会直接进仓库。**逐个点名添加**是最可靠的防线。

### 3.3 本地开发不受影响的原理

| 场景 | 行为 |
|---|---|
| 你本地打开 `index.html` | 加载 `profile.local.js` → 看到真实数据，**与脱敏前完全一致** |
| 别人 clone 后打开 | 无 `profile.local.js` → 回落中性示例值，功能完整可跑 |
| 你改了真实数据 | 只改 `profile.local.js`，该文件不进仓库，无需任何额外操作 |
| 你想改代码逻辑 | 正常改 `index.html` 并推送，与画像数据互不干扰 |

**结论：日常开发零成本。** 唯一的纪律是——**身体数据只写进 `profile.local.js`，不要写回 `index.html`**。

## 四、应急：已推送仓库的历史清洗

> 本节仅在"**敏感信息已经进入远程仓库的提交历史**"时使用。本仓库当前**不需要**执行。

**关键认知**：单纯 `git rm` 再提交**无效**——旧提交里仍有该文件，任何人 `git log -p` 都能翻出来。必须**重写历史**。

**推荐工具：`git filter-repo`（官方推荐，取代已废弃的 `filter-branch`）**

```bash
# 安装
brew install git-filter-repo

# 1) 先备份整个仓库（重写历史不可逆）
cp -r ~/WorkBuddy/2026-08-26-11-51-25 /tmp/tm-backup

# 2) 从全历史中彻底移除敏感文件
cd ~/WorkBuddy/2026-08-26-11-51-25
git filter-repo --path profile.local.js --path docs/系统介绍-v3.28.md --invert-paths

# 3) 若敏感内容是"字符串"而非整份文件，用替换：
#    建 expressions.txt，每行格式：  旧字符串==>替换值
git filter-repo --replace-text expressions.txt

# 4) 强制推送（会重写远程历史）
git push --force-with-lease origin main
```

**必须配套做的事：**

1. **强制推送后，通知所有协作者重新 clone**——他们的本地历史已与远程分叉。
2. **若密钥/token 曾泄露，立即在服务端吊销并轮换**。清理历史**不能**挽回已泄露的凭据——爬虫和 fork 可能早已抓走。这是本流程里唯一"无法靠技术补救"的一环。
3. 平台侧可能仍缓存旧提交（如 GitHub 的不可达对象），必要时联系平台支持清理。

> 本项目零后端、无密钥，第 2 条不适用；但若你 fork 后接入了任何第三方服务，请务必遵守。

## 五、操作红线（务必遵守）

| # | 红线 | 原因 |
|---|---|---|
| 1 | **身体数据只写 `profile.local.js`** | 写回 `index.html` 会随代码进仓库 |
| 2 | **提交前必看 `git status`，逐文件 `git add`** | 防临时文件被无差别暂存 |
| 3 | **不要为了图快用 `git commit -a` / `git add -A`** | 同上 |
| 4 | **不要删除或改写 `.gitignore` 里的 `!profile.local.example.js` 行** | 少了模板，clone 者无从配置 |
| 5 | **新增含个人数据的文件时，同步加进 `.gitignore`** | 忽略规则需主动维护 |
| 6 | **不要把 `*.bak-*` / `*.pre-*` 改名后再提交** | 改名绕不过内容——**脱敏前的备份文件本体含真实数据**，必须整份排除 |
| 7 | **换新仓库时重新设置 `--local` 匿名身份** | 仓库级配置不随代码复制 |
| 8 | **公开前再跑一次 `sh tests/run.sh`** | 脱敏断言是最后一道自动防线 |

## 六、自检命令速查

```bash
cd ~/WorkBuddy/2026-08-26-11-51-25

# ① 当前会入库哪些文件
git ls-files

# ② 忽略规则是否按预期生效（应输出"已忽略/可入库"）
git check-ignore -v profile.local.js
git check-ignore -v profile.local.example.js   # 应"未命中"= 可入库

# ③ 工作区有无未跟踪的敏感文件漏网
git status --short

# ④ 全目录扫描敏感文件类型
find . -type f \( -name '*.env' -o -name '*.pem' -o -name '*.key' \
  -o -name 'credentials*' -o -name '*secret*' -o -name '.netrc' \) -not -path './.git/*'

# ⑤ 提交历史里的作者身份
git log --all --pretty='%an <%ae>'

# ⑥ 全历史内容敏感词扫描
git log --all -p | grep -niE '(api[_-]?key|secret|token|password)[[:space:]]*[:=]|/Users/'

# ⑦ 回归测试（含脱敏断言）
sh tests/run.sh
```

**② 和 ⑤ 是两条最容易被忽略、代价又最高的检查**：② 防止模板被误排除或真实画像被误纳入；⑤ 防止真实邮箱随提交历史永久公开。

## 七、当前待办

推送是**唯一尚未执行**的步骤——它需要你的仓库地址，且属于对外可见的不可逆操作，故未自动执行。

```bash
git reset --soft $(git rev-list --max-parents=0 HEAD)

```

该操作只影响本地、尚未推送，安全。**推送之后**再想合并就需要强制推送了，所以决定要在推送前做。
