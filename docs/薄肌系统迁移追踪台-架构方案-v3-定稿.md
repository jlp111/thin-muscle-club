## 4. Q8 的依据：DERIVED 的时序陷阱

**实测模块顺序：**

```
PERSONAL      L1004
DERIVED       L1014   ← IIFE 立即求值
KbData        L1040
Store         L2057
Store.load()  L4844   ← 数据加载
```

**`DERIVED` 比数据加载早了 3,830 行**，且其值已被**烘焙进 KbData 的文案字面量**：

```js
points:['心率' + (DERIVED.hrText||'低-中') + 'bpm', ...]
how:'1.6-2.2 g/kg' + (DERIVED.proText ? '（按当前画像约 '+DERIVED.proText+'）' : '') + ...
```

**因此「打通内容层」的真实成本**不是 v2 写的 +0.5 人日，而是：
把 `DERIVED` 改成可重算 → 把 `KbData` 改成惰性工厂 → 13 个页面全部改走工厂读取 → 每次画像保存后触发重建。**这是全工程风险最高的改动。**

**✅ 采用旁路方案（低风险、时序天然正确）：**

在 `profile.local.js` 之后、主脚本之前插一支内联脚本：

```html
<script src="profile.local.js"></script>
<script>
/* 向导采集的画像回填：仅当 profile.local.js 未提供时生效，
   保证本地真实画像始终拥有最高优先级。执行时机在主脚本之前，
   因此 DERIVED / KbData 求值时数据已就位 —— 无需改动它们的时序。 */
(function(){
  if (window.__TM_PROFILE__) return;              // profile.local.js 优先
  try{
    var raw = localStorage.getItem('thinMuscle.trainSys.v1');
    if(!raw) return;
    var p = JSON.parse(raw).data.profile;
    if(p && p.weight) window.__TM_PROFILE__ = p;
  }catch(e){}
})();
</script>
```

收益：向导对**没有 `profile.local.js` 的用户**（开源受众）真正生效；你的本地画像优先级不变；完全不触碰 DERIVED/KbData。

### 5.2 组件映射

**直接映射（30+ 项）**：`.panel`→`.card`、`.hero-band`→`.hero`、`.stat`→`.metric-*`、`.bar`→`.progress`、`.btn*`→追踪台按钮组、`.tag`→`.status-tag`、`table.data`→`.data-table`、`.setrow`→`.set-row`、`.modal-backdrop`→`.overlay`、`#toast`→`#toastStack`、`.empty`→`.empty`、`.warn-box`→`.warning`、`.fail-step`→`.insight`、`.food-opt`→`.food-option`…

**需新建 6 个原子**（全部基于追踪台令牌）：
`.kv`（字段行，替代 `.fld`）· `.kv-grid` · `.tier-tag` · `.kb-card` · `.fold`（追踪台对 `details` 样式化为 0 条，实测确认必要）· `.matrix`（周矩阵）

**颜色自定义需重映射 6 条规则**（不是 3 条——含配套基础样式）：

| 上下文 | 规则 |
|---|---|
| 基础·浅色 | `#page-today>.grid>.card:nth-child(2\|3)`（暖色底 / 青绿底） |
| 基础·深色 | 同上两条 |
| 自定义色 | 同上两条 → `--custom-button-soft` / `--custom-primary-soft` |

建议：改用显式类名 `.card.tint-peach` / `.tint-mint` 替代 `:nth-child`（结构选择器会因插卡静默错位）。
